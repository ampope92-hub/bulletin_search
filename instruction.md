We publish a conservation newsletter and the back issues are the only record of a lot of the studio's work. There are 220 of them in /app/corpus, one markdown file per issue, and each issue is a masthead line followed by a dozen or so short items that have nothing much to do with each other. People come to us asking things like which issue was the one about the moth damage in the tapestry, and at the moment somebody goes off and reads until they find it. I want that answered by a program instead. /app/queries/dev.json is forty questions we already worked the answers out for, with the issue ids listed against each one, and /app/queries/graded.json is sixty more where I have kept the answers back.

There is a Cargo project at /app/search with candle, hf-hub and tokenizers already wired into Cargo.toml. Fill in src/main.rs so that a fresh cargo run --release reads /app/corpus and /app/queries/graded.json and writes /app/rankings.json, a JSON array with one object per question holding query_id and issues, where issues is exactly ten different issue ids in order with the best one first, no issue listed twice. sentence-transformers/all-MiniLM-L6-v2 at revision 1110a243fdf4706b3f48f1d95db1a4f5529b4d41 is there for the text work if you want it, the box is online so you can pull it down from the Hub, and how you rank is up to you; but stay with the crates already in Cargo.toml and leave Cargo.lock alone, because nothing new gets installed on the machines this runs on and they build from that lock. We build with our own copies of both files and check yours against them. We score it as mean nDCG at 10, counting an issue as right if it is on our list for that question, and there is more than one right issue for some of them, and it has to come in at 0.65 or better. Last thing and it matters more than it sounds: we run the same program every month against a fresh batch of questions, on a box with no network where the model is already sitting in the hf-hub cache, that revision's config.json, tokenizer.json and model.safetensors and nothing else, so it has to work off whatever query file it is handed rather than the one you can see, and the issue files may carry different ids by then, so take the ids from the directory you are given rather than from anything you remember, and on that run it has to come in at 0.60 or better. Don't leave a rankings.json checked in, whatever is sitting there gets cleared before the run.
